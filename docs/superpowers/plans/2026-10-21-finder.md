# 나에게 맞는 영양제 찾기(셀프체크, finder.html) 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** "어떤 영양제를 먹어야 하지?" 단계의 방문자가 질문 6개에 답하면 추천 성분·읽어볼 가이드·추천 조합의 궁합·하루 복용 시간표를 한 화면에서 받고, 내 영양제 저장·궁합 체크·공유 링크로 이어지는 도구형 페이지를 만든다. 새 데이터 없이 가이드 요약 색인(87편의 핵심 성분)·궁합 판정(`resolvePair`)·시간표(`schedule.js`)·내 영양제(`store.js`)를 조합한다. '영양제 추천' 키워드를 받는 페이지이기도 하다.

**Architecture:** 질문과 "답 → 가이드" 규칙은 수동 데이터 `data/finder.json` 한 파일에 둔다. 순수 로직 `assets/js/finder.js`(답변 파싱·직렬화·규칙 매칭·가이드 점수·성분 점수·제한·플래그)는 `window.Finder` 와 `module.exports` 둘 다 노출해 Node 로 테스트한다. 페이지 `finder.html` 은 빌드(`render_finder`)가 `finder.json` 에서 질문 폼을 정적 HTML 로 생성하고(검색엔진·JS 없는 환경), `assets/js/pages/finder.js` 가 폼을 가로채 결과를 그린다. 답은 주소 쿼리(`?age=30s&concern=fatigue,sleep…`)로 직렬화되어 공유·재방문이 된다. 추천 성분은 매칭된 가이드의 핵심 성분을 가이드 점수와 순서 가중으로 합산해 고르고, 어린이·청소년·임신·수유는 해당 가이드의 성분 범위로 제한한다(`restrictTo`). 규칙 판정·시간표는 기존 모듈을 그대로 쓰고 파이썬에 복제하지 않는다.

**Tech Stack:** 정적 HTML(빌드 생성) + Vanilla JS(IIFE + module.exports) + `assets/css/style.css` 의 `.finder-*` 일반 CSS, 파이썬 빌드 검증(`validate_finder`)·`unittest`, `node --test`.

**Spec:** 2026-10-21 분석 4번(셀프체크). 선행 작업: `docs/superpowers/plans/2026-10-21-keyword-pages.md`(완료).

## Global Constraints

- CLAUDE.md 규칙: 생성 파일은 빌드로만(`finder.html` 포함), JS·CSS 수정 뒤 빌드, `check_site.py` 실패 0, 푸시 전 `npm run assets`.
- 추천 문구는 가이드·성분 사전에 이미 있는 표현(식약처 인정 범위)만 조합한다. 결과 화면은 "이 가이드들이 핵심 성분으로 꼽은 성분"이라는 근거를 함께 보여주고, 질병 치료·효과 보장 표현을 쓰지 않는다. 임신·수유·어린이·약 복용·수술·항암 중은 주의 상자를 띄우고 의사·약사 상담을 안내한다.
- 답변은 서버로 보내지 않고 저장하지도 않는다(주소 쿼리에만). 내 영양제 저장은 기존 `[data-my-add]` 공통 처리로 한다.
- 응답·커밋·주석·문서는 한국어, 커밋 끝에 `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>`.

## Review Focus

1. 어린이·청소년·임신·수유 답변에 다이어트·허브 성분이 추천되면 안 된다. → `restrictTo` 가 해당 가이드 성분으로만 제한, Node 테스트.
2. 규칙·옵션·가이드 slug·성분 id 가 어긋나면 빌드가 실패해야 한다(조용히 빈 결과 금지). → `validate_finder`, 파이썬 테스트.
3. 주소 쿼리의 모르는 값·초과 선택은 버리고 페이지가 죽지 않아야 한다. → `Finder.parse`, Node 테스트.
4. JS 없이도 질문·설명·FAQ 가 HTML 에 있어야 한다(검색엔진). → `render_finder` 정적 폼, 파이썬 테스트.
5. '없음/해당 없음' 옵션은 같은 질문의 다른 선택을 지우고, 고민은 최대 3개. → 페이지 JS, 브라우저 확인.
