# 전문의약품(처방약) 허가정보 수집 확장 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 약별 영양제 가이드의 처방약 분류(스타틴·갑상선약·와파린·항생제·골다공증약·메트포르민·이뇨제·레티노이드·메토트렉세이트·먹는 스테로이드)에 식약처 허가 제품 목록을 채우고, 그 제품을 의약품 검색·상세(`drug.html`)에서도 찾을 수 있게 한다. e약은요(의약품개요정보)는 일반의약품 중심이라 처방약이 거의 없으므로, 의약품 제품 허가정보(목록) API 를 처방약 규칙의 주성분(영문 INN)으로 검색해 전문의약품 허가 목록을 따로 모은다.

**Architecture:** `scripts/fetch_drugs.py` 에 수집 단계 3) 을 더한다 — `load_rx_rules`(`data/drug-pairings.json` 규칙 중 `data/drug-guides.json` 이 `rx` 로 표시한 것) → `fetch_rx`(규칙·검색어별로 `spclty_pblc=전문의약품` + `item_ingr_name=<INN>`(머리글자 대문자 → 원문) → `item_name=<한글 성분명>` 후보를 차례로 시도, 필터가 안 먹는(전체 건수와 같은) 응답은 버림, 100건씩 페이지, 실행당 호출 예산 `DRUG_RX_BUDGET`(기본 300) 안에서 진행 위치를 캐시 `data/drugs/rx.json` 에 남기고 다음 실행에서 이어 감, 완료된 규칙은 30일마다 재수집) → `normalize_rx`(허가 항목 → 상세 레코드, e약은요 본문은 비우고 `source: "mfds-permit"`) → `rx_records`(허가 취하·취소 제외, 규칙마다 브랜드 가중치 → 브랜드 키워드 → 허가일 최신 순 `DRUG_RX_PER_RULE`(기본 200)건, 여러 규칙에 겹치면 한 번) → e약은요에 없는 품목만 검색 색인·상세 조각에 합친다. `--rebuild` 는 API 없이 `rx.json` 으로 같은 레코드를 다시 만든다(저장된 `mfds-permit` 레코드는 e약은요 행으로 되돌리지 않음). 빌드의 `drug_guide_model` 은 상세 조각을 그대로 읽으므로 처방약 가이드의 '이 분류의 약' 목록이 자동으로 채워지고, `pages/drug.js` 는 `source === "mfds-permit"` 이면 빈 e약은요 항목 여섯 개 대신 허가정보 안내와 의약품안전나라(허가 상세) 링크 한 섹션을 보여 준다.

**Tech Stack:** 파이썬 수집기(`requests`, 공공데이터포털) + 기존 빌드·JS. 이 저장소 작업 환경에서는 외부 API 를 호출할 수 없어 가짜 응답으로 `unittest` 를 만들고, 첫 실수집은 `.github/workflows/update-data.yml`(매일 03:15 KST, `DATA_GO_KR_KEY` Secret) 이 한다.

**Spec:** 2026-10-22 약별 영양제 가이드 계획의 후속(처방약 분류는 e약은요에 약이 없어 수동 대표 성분·제품만 표기 → 허가정보 수집으로 목록 채움).

## Global Constraints

- CLAUDE.md 규칙: 생성 파일은 빌드로만, 점검 실패 0, 푸시 전 `npm run assets`. API 키는 Secrets/.env 에만.
- 의약품에는 구매 링크를 넣지 않는다. 처방약 설명은 식약처 허가정보(주성분·분류·허가일)만 보여 주고 효능·용법은 의약품안전나라 링크로 안내한다(e약은요 본문을 지어내지 않음).
- 공공데이터포털 개발계정 일일 1,000건 기준으로 e약은요(약 50회)·허가정보 연결·전문의약품 수집(기본 300회)이 한 실행(시간 예산 780초) 안에 끝나야 한다. 수집 상한(규칙당 200건)으로 검색 색인(`names.json`) 크기를 억제한다.
- API 파라미터 이름(`item_ingr_name`·`item_name`·`spclty_pblc`)은 기존 코드가 쓰는 `item_seq`·`spclty_pblc` 와 같은 명명 규칙을 따른다고 보되, 지원되지 않는 경우(전체 목록이 그대로 옴·HTTP 400)를 감지해 다음 후보로 넘어가고 로그에 남긴다.
- 응답·커밋·주석·문서는 한국어, 커밋 끝에 `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>`.

## Review Focus

1. 예산을 넘기면 진행 위치(검색어·페이지·후보)가 캐시에 남고 다음 실행에서 정확히 이어진다. → `test_fetch_rx_budget_resume`.
2. 필터가 안 먹는 파라미터는 규칙 안에서 다시 쓰지 않고, 0건 후보는 다음 후보로 넘어간다. → `test_fetch_rx_paginates_and_falls_back`.
3. 허가 취하·취소 제품은 빠지고, 규칙당 상한과 중복 제거가 지켜지며, e약은요 레코드가 우선한다. → `test_rx_records`.
4. `--rebuild` 가 `mfds-permit` 레코드를 e약은요 행으로 되돌리지 않는다. → `test_rebuild_rows_excludes_permit_only`.
5. 처방약 가이드가 허가정보 제품을 목록에 싣고(`drug_guide_model`), 의약품 상세는 e약은요 빈 항목 대신 안내·링크를 보여 준다. → `test_rx_guide_lists_permit_only_drugs`, Playwright(가짜 상세 조각).
