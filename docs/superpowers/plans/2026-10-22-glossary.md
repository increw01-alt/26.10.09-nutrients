# 영양제 용어 사전(glossary.html, term/<slug>.html) 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** "rTG 뜻", "생체이용률이란", "상한섭취량", "보장균수 CFU", "개별인정형 고시형 차이", "지표성분" 같은 용어 검색을 받는 용어 사전을 만들고, 가이드·성분·비교·약별 페이지 본문에 처음 나오는 용어를 자동으로 용어 페이지에 연결해 사이트 안 체류와 내부 링크를 늘린다. 용어는 성분 사전과 겹치지 않게 '성분 이름'이 아니라 제형·흡수·형태·섭취 기준·제도·상호작용·검사 수치를 다룬다.

**Architecture:** 수동 데이터 `data/glossary.json`(`_meta.categories` + items: slug·term·en·aliases(자동 링크용 표기)·category·short(한 줄 뜻)·body(문단)·label(라벨·검사지에서 보는 법, 선택)·related(용어 slug)·ingredients(성분 id)·guides(가이드 slug))을 `build_site.py` 의 `glossary_model` 이 검증·정리하고 `render_term` 으로 `term/<slug>.html`(뜻·라벨에서 보는 법·관련 용어·관련 성분·관련 가이드, DefinedTerm+Breadcrumb JSON-LD), `render_glossary_hub` 로 `glossary.html`(검색 상자·초성/알파벳 필터·분류별 카드·FAQ, DefinedTermSet JSON-LD), `data/glossary-index.json`(검색·자동 링크용 요약 색인)을 쓴다. 본문 자동 링크는 `TermLinker`(별칭을 긴 것부터 맞추고, 영문·숫자 별칭은 앞뒤가 영문·숫자가 아닐 때, 한글 별칭은 앞이 한글이 아닐 때만, 페이지당 용어마다 첫 등장 한 번, 최대 12개, 자기 용어 페이지는 제외)가 HTML 이스케이프된 본문 조각에만 적용되어 가이드(소개·핵심 성분 설명·조합 메모·본문·팁·주의·FAQ)·성분 페이지(요약·권장량 메모·시간 메모·주의·FAQ, SSR)·성분 비교(소개·핵심 차이·이런 분은·같이 먹기·FAQ)·약별 가이드(소개·요약 표·좋은/주의 이유·복용 요령·FAQ)·기능성 허브(소개)에 들어간다. 성분 페이지는 `pages/ingredient.js` 가 본문을 다시 그리므로 같은 규칙의 `assets/js/terms.js`(순수 함수, Node 테스트)가 `D.glossary()` 색인으로 같은 자리에 링크를 넣는다. 통합 검색 결과(`pages/search.js`)와 전역 검색 오버레이(`layout.js`)에 '용어 사전' 묶음을 더한다.

**Tech Stack:** 정적 HTML(빌드 생성) + Vanilla JS 소량(`terms.js`, `pages/glossary.js` 필터) + 기존 CSS(`.chip`·`.ing-card`·카드 재사용, `.term-link`·`.term-card` 소량) + 파이썬 빌드·`unittest`, 점검 `check_site.py`(`term/` 포함).

**Spec:** 2026-10-21 분석 5번(용어 사전: 새 데이터 파일과 빌더, 본문 자동 링크는 렌더 단계). 용어 80개.

## Global Constraints

- CLAUDE.md 규칙: 생성 파일은 빌드로만, 점검 실패 0, 푸시 전 `npm run assets`.
- 용어 설명은 사실 관계·제도·단위 설명에 한정하고, 성분의 기능성 표현은 식약처 인정 문구 범위를 지키며 질병 치료·예방 표현을 쓰지 않는다. 검사 수치의 기준값은 널리 쓰이는 일반 기준만 적고 '검사 기관·개인에 따라 다르다'를 붙인다.
- 자동 링크는 제목·헤더·버튼·칩에는 넣지 않고 본문 조각에만 넣는다. 별칭은 다른 용어·성분명과 겹치지 않는 분명한 표기만 쓴다(빌드가 별칭 중복을 검증).
- 한 검색 의도에 한 페이지: 용어 페이지 제목 틀 "`{용어}`({영문}) 뜻 — 영양제 용어 사전". 성분 사전(성분 이름)과 주제가 겹치는 용어는 넣지 않는다.
- 응답·커밋·주석·문서는 한국어, 커밋 끝에 `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>`.

## Review Focus

1. slug·별칭 중복, related 용어·성분 id·가이드 slug 오류는 빌드가 실패해야 한다. → `validate_glossary`.
2. 자동 링크는 첫 등장만, 경계 규칙(헴철/비헴철, rTG/xrTG)을 지키고, 이스케이프된 텍스트 밖(태그 안)에는 절대 넣지 않는다(본문 조각 단위로만 호출). 파이썬·JS 규칙이 같아야 한다. → 두 테스트가 같은 사례를 검사.
3. 용어 페이지는 자기 자신을 링크하지 않는다. → `exclude`.
4. 새 디렉터리 `term/` 를 사이트맵·스탬프·PWA·점검·Tailwind 가 모두 포함한다.
5. 구형 브라우저(lookbehind 미지원)에서는 JS 링크가 조용히 꺼진다. → `try/catch`.
